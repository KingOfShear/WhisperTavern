# 可逆安装范式落点草案（Reversible-Install Draft）

> 状态：**规划备忘录（非 spec）**。本文为"向本项目引入『可逆安装』范式"的落点推演与挂接建议，供 WP 决策引用；**不另产平行详设**——一旦决定引入到具体模块，按纪律 3 先落 spec 骨架并登记 §38，本文随之收敛为决策依据。
> 版本：v0.1 · 修订：2026-09-07 初稿（承接外部参照 `hanshuang-codex/install.ps1` 分析，MIT）。

## 1. 范式的来源与内核

来源：`hanshuang-codex`（MIT）的 `install.ps1`（配置 `model_instructions_file` 的**备份→注入→回滚→无残留**）。

内核四要素：

1. **托管区 + 复制式安装**：目标文件被**复制**进托管目录，安装只改副本，不碰用户原位文件。
2. **状态文件记录"改动前的那一行"**：`{ hadLine, previousLine, configExisted }`——回滚是**精确还原**原行，而非兜底覆盖整文件。
3. **作用域编辑**：只改一个 key 的一行（正则单匹配），影响面收敛到极小。
4. **删除式回滚 + 无残留**：卸载删副本 + 还原行 + 清空态文件，目录空则连目录删。

## 2. 边界约束（先过 AGENTS 纪律，再谈落点）

- **纪律 5**：本范式**不产生新模块/Service/Manager**。可逆性是既有导入/注册流程里的一个**步骤与一组状态字段**。
- **运行态是 DB 而非 TOML**（决策 2）：文件编辑那半段在本项目**几乎不适用**；真正契合的是"托管区 + 精确状态 + 可逆"的**数据/资产层语义**。
- **决策协议**：凡触碰到注册/表结构/公共契约（见 §5），按协议 c 停下问，并登记 §38。

## 3. 落点 A（近期）— 资产导入可逆化

**范围**：S9/WP1.1a 卡导入（✅，characters 注册索引 + 资产落 `data/`）、S10/WP1.1b 世界书导入（进行中）。

**现状缺口**：导入 = 写入资产文件 + 注册 DB 索引 + version 快照（决策 11 混合资产存储）；**当前导入不可撤销**（无"导入前状态"记录）。

**对应到 install.ps1 的映射**：

| hanshuang 字段 | 本项目语义 |
|---|---|
| `managed-prompts/`（托管目录） | `data/` 资产区（.dgcard/.dgworld） |
| `targetPrompt`（复制进来的副本） | 导入后落地的资产文件 |
| `install-state.json` | 导入登记记录（新增，放 DB 或随资产元数据） |
| `previousLine` / `hadLine` | 导入前的同名资产/索引引用（`previousAssetRef` / `hadAsset`） |
| `configExisted` | 该资产 id 原是否已注册 |

**建议的最小步骤（不新开模块）**：在 st-compat 导入落库时，先捕获"目标 asset_id 的既有注册态 + 预期落位"，导入后写 `importedAt / hadAsset / previousAssetRef`；"撤销导入" = 删副本 + 还原注册态（原无则注销）+ 清登记。见 §6 修复两坑。

**验收锚点**（技术-design §37 四问）：数据/注册层改动——不改 Prompt、不破 Cache、不影响 Agent；Debug 靠 fixture 回放 + 报告（§8 测试基建）。『撤销导入』作为导入功能的功能性验收项纳入对应 WP。

## 4. 落点 B（远期）— 插件安装可逆化（P5）

**范围**：P5 插件 API（§29、决策 32 #16 Plugin 信任分档）。

**建议**：插件安装直接采用本范式为装载规范——插件包复制进托管目录 + `install-state` 记录装载前状态 + 卸载删副本还原、无残留。**具体字段/契约留给插件 spec**（纪律 3），本文不预写。

## 5. 决策协议提示（对落点的判断）

- 落点 A 若把"导入登记记录"新增为 DB 表/字段 → **触碰表结构**（协议 b/c），须停问 + 登记 §38。
- 落点 B 属 P5 新契约 → 插件 spec 定义时按协议 a/c。

## 6. 相对原来源的两处修复（借鉴时必须改掉）

1. **对称还原**：来源在 `configExisted=false` 时卸载只删行、残留空配置文件。本项目：若"原不存在"则必须还原为"不存在"（删副本 + 注销 + 删除因此新建的目录/空态）。
2. **幂等 + 原子写 + key 唯一**：来源正则只替换首个匹配、无锁，多实例并发会互相覆盖。本项目：同一资产 id/插件 id 幂等安装，状态写入原子（DB 事务或临时文件 rename），托管 key 保证唯一。
